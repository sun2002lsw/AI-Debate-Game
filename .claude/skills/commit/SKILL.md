# 커밋 스킬

현재 작업 디렉토리의 변경 사항을 분석하고, 논리적 단위로 분리하여 한글 커밋 메시지와 함께 커밋합니다.

## 절차

### 1단계: 현재 상태 파악

아래 명령어를 **병렬로** 실행하여 현재 상태를 파악합니다:

- `git status` — 변경/추가/삭제된 파일 목록 확인 (절대 -uall 플래그 사용 금지)
- `git diff` — unstaged 변경 내용 확인
- `git diff --cached` — staged 변경 내용 확인
- `git log --oneline -10` — 최근 커밋 히스토리 참고

### 2단계: 변경 사항 분석 및 그룹 분리

변경된 파일들을 **기능/목적별로 논리적 그룹**으로 분리합니다:

- 같은 기능에 속하는 파일들은 하나의 커밋으로 묶기
- 서로 무관한 변경은 별도 커밋으로 분리
- 각 그룹에 적절한 한글 커밋 메시지 초안 작성

### 3단계: 커밋 계획 보고

아래 형식으로 사용자에게 커밋 계획을 보고합니다:

```
## 커밋 계획

### 커밋 1: <한글 제목>
- **파일**: <파일 목록>
- **설명**: <변경 내용을 구체적으로 설명하는 1~3문장>

### 커밋 2: <한글 제목>
- **파일**: <파일 목록>
- **설명**: <변경 내용을 구체적으로 설명하는 1~3문장>
```

그리고 AskUserQuestion 도구를 사용하여 사용자에게 승인을 요청합니다:
- "이대로 커밋 진행" 옵션
- "수정 필요" 옵션

### 4단계: 커밋 실행

사용자가 승인하면 각 그룹을 순서대로 커밋합니다:

1. `git add <해당 파일들>` — 개별 파일을 명시적으로 스테이징 (git add -A 사용 금지)
2. `git commit` — HEREDOC 형식으로 커밋 메시지 전달

커밋 메시지 형식:
```bash
git commit -m "$(cat <<'EOF'
한글 커밋 제목

변경 내용을 구체적으로 설명하는 본문.
무엇을 왜 변경했는지 1~3문장으로 작성.

Co-Authored-By: Claude Opus 4.6 <noreply@anthropic.com>
EOF
)"
```

- 제목: 변경의 핵심을 요약하는 한 줄 (명령형)
- 본문: 제목과 빈 줄로 구분하며, 변경의 구체적 내용과 이유를 설명

3. 모든 커밋 완료 후 `git log --oneline -5`로 결과를 보여줍니다.

## 주의사항

- .env, credentials 등 민감한 파일은 커밋에 포함하지 않습니다
- 사용자 승인 없이 절대 커밋하지 않습니다
- push는 하지 않습니다 (사용자가 명시적으로 요청한 경우에만)
- pre-commit hook 실패 시 --amend 대신 새 커밋을 생성합니다
